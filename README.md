# 图纸拆分自动化

本仓库用于每小时扫描 Google Drive `王振海/待拆图纸`，从 FastCAM 排版图中识别零件索引，严格匹配基础汇总表，生成旧版格式 Excel，并在成功后给原图片文件名增加 `完成_` 前缀。

## 固定目录

- `王振海/待拆图纸`：输入图片；跳过以 `完成_` 开头的图片。
- `王振海/正在加工`：第一优先基础数据。
- `王振海/拆图模版`：第一优先零匹配时才使用。
- `王振海/拆图结果`：输出 Excel。

## 固定命名

真实历史规则：

- 输入图片：`#2323 T150退400X1760.jpg`
- 成功后的图片：`完成_#2323 T150退400X1760.jpg`
- 输出 Excel：`#2323_完成.xlsx`

Excel 使用图片文件名第一个空格前的“板材主名称”，不把厚度、余料尺寸等后缀带入结果文件名。

## 匹配与重量

普通零件必须按以下五项唯一匹配：订单号、图号、厚度、坡口、基础件数。任何字段缺失、冲突或多匹配时，该图片失败且不改名。

```text
单件重量(T) = 基础表总净重(kg) / 1000 / 基础件数
本次拆分重量(kg) = 单件重量(T) × 图片拆分数量 × 1000
```

图片钢板重量只用于复核，不用于反推、分摊或修改基础重量。

基础文件同时支持普通汇总表 `.xlsx` 和订单模板 `.xlsm`。程序按表头识别 kg 或 t，不用面积重新推算缺失重量。特殊订单 `26511255302-0814` 仅在订单、厚度、坡口和件数一致时，按图号末两段做唯一匹配。

基础数据兼容 `.xlsx` 汇总表和 `.xlsm` 模板；`.xlsm` 的“重量”列按吨读取，带 `(kg)` 的重量列按公斤读取。

已使用 2323、2324、2325、2326、2331、2332、2333 七张历史图做本地端到端回归，OCR 字段、零件明细、拆分重量、差额与历史 Excel 一致。生产 Drive 写回仍须先在 GitHub Actions 中完成一次 `dry_run=true` 验证。

## GitHub Secrets

- `GOOGLE_SERVICE_ACCOUNT_JSON`：完整服务账号 JSON；服务账号必须至少拥有 `王振海` 根目录的编辑权限。
`王振海` 根目录 ID 已配置在工作流中，不需要重复添加 Secret。

## 执行方式

手动测试时优先选择 `dry_run=true`，程序会真实下载、OCR、匹配和生成文件，但不上传结果、不修改原图名。确认运行日志无误后，再用 `dry_run=false` 执行。

推送到 `main` 时自动执行一次只读回归：真实读取 Drive、OCR 和生成本地结果，但不上传、不改图片名。UTC cron `0 * * * *` 已开启，每小时运行一次生产流程；它不依赖本地 Mac 开机。单张图片发生识别或匹配异常时，该图片不会生成结果，也不会改名。

## 安全与幂等

- 只有 Excel 已生成并通过公式/错误扫描后才上传。
- 只有上传成功后才给原图片增加 `完成_`。
- 结果目录已有同名 Excel 时更新该文件，避免重复创建。
- 跳过新规则前缀 `完成_`，也跳过历史规则后缀 `_完成`，避免重复处理旧图片。
- GitHub Actions 使用并发锁，避免两个生产任务同时处理同一图片。
- 公司原图、汇总表、生成结果和凭据均不提交到仓库。
